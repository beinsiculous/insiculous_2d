# Editor Crate — Agent Context

You are working in the editor crate. UI panels, tools, inspector, hierarchy — the editor's data and widgets.
This crate has NO dependency on engine_core. It depends on: ecs, ui, input, renderer, physics, common, and music_midi without its `synth` feature (the composer edits and saves songs, never renders them — `cargo test -p editor` alone is what proves that build).

## Architecture
```
EditorContext (selection, tool state, play state, camera, theme, status_bar, fonts, inspector_scroll)
│   (CommandHistory itself lives on editor_integration's EditorGame and is threaded into panel renderers)
├── Panels: SceneView, Hierarchy, Inspector, AssetBrowser, Composer (hidden until a song asks for it), Console (hidden until View → Console asks for it), External Tools (hidden until Edit → External Tools… asks for it)
├── Dock layout: dock.rs (multi-panel docking, narrow mode below MIN_CENTER_WIDTH)
├── Menu / StatusBar (top + bottom chrome; an error naming a file carries its request, and a click on it opens the file); Toolbar + PlayControls in the scene view's toolbar strip
├── Tools: Select, Move, Rotate, Scale (Q/W/E/R shortcuts)
├── Gizmos: Translate, Rotate, Scale handles
├── Picking: EntityPicker, SelectionRect, screen_to_world()
├── Inspector: Generic serde-based + per-component editors with writeback
│   (one renderer: `InspectorFrame.read_only` draws every row's value in
│   place of its control while a play session runs; sections collapse and
│   an Advanced disclosure hides the rarely-touched fields)
├── Undo/Redo: CommandHistory + EditorCommand trait, StoredComponent for restore
├── Theme: EditorTheme with 30+ color tokens (mockup-derived)
└── Play state: EditorPlayState (Editing/Playing/Paused), WorldSnapshot
```

## File Map
### State + chrome
- `context/` — EditorContext struct (selection, tools, state, view toggles, game frame dimensions, theme, fonts, inspector_scroll).
- `theme/` — EditorTheme: WCAG surface ladder `surface_0..surface_4` with luminance guard tests (≥1.35:1 adjacent / ≥3:1 border, overlay tones subdued against selection accent, game frame distinctness, grid axis hierarchy), muted overlay tokens (`game_frame`, subdued grid and colliders), the piano roll's four (`note_fill`, `note_selected_border`, `key_black`, `playhead`, each guarded at 3:1 over the roll), style converters, and `ui_theme()`.
- `command_api/` — CLI/API dispatch (query list/describe/selection/scene/status/commands and write set/add/remove/rename/delete/select/undo/redo/batch) through CommandHistory; `docs/EDITOR_COMMAND_API.md`. `command_api/song.rs` is the `song …` arm: its parser, the `song` and `song notes` answers, the pure song writes through `SongDocument::apply`, and `song_write_refusal` (Playing and Paused, an open scene batch) the host's song verbs share.
- `song/` — the composer's song, a second document: `SongDocument` (the sidecar and the MIDI data, its path, the file it was imported from, `EditingPolicy` from the import's report — `Refused` refuses score edits only, so the map of any playable file edits and saves; the `.mid` exactly as last read or written, `source_bytes`, and the two fingerprints, `score_fingerprint` and `map_fingerprint` — `None` while no sidecar is on disk; `baseline_export`, the data's own `write_smf` as the score was last loaded or written — the score is the engine's (`is_score_authored`) exactly while the data's export now differs from it: content, since the history merges a gesture's frames into one entry and evicts its oldest past its cap, and an edit undone after a save followed by another edit nets to nothing in any count, while the bytes tell; not the loaded bytes themselves, which an unedited export may re-encode; `None` when the data would not export, which keeps the score the file's and makes the policy `Refused` — `EditingPolicy::for_score` is the one rule, so `editing()` says what `apply` does; the home `LICENSE`, written before the sidecar's second look, is put back on a refusal there, and the refusal is answered even when the put-back fails; dirty = its watermark moved OR it was never saved OR its sidecar is not on disk), `SongEdit` and its merge rule (`edit.rs`; `changes_score` names the score edits — a `Batch` when any member is, however deep; `edit/apply.rs` checks and applies each variant, a sidecar edit through `SongFile::check_schema` on the file it would produce, `Batch` on copies so a refused member lands nothing), the exact undo/redo `Change`s (`change.rs`), `SongHistory` (`history.rs`, the scene watermark's contract and nothing of its session floor; `revision`, which a host compares to know the document moved under a prepared song; `drop_entries`, the watermark following the entries kept), `follow.rs` (`adopt_score` — a new `.mid` taken whole, the map and its unsaved edits kept, the score's entries dropped, the track diff's lines returned — and `reload_map`, the sidecar re-read with the score's edits kept), `SongSelection`, and the save journal and open's recovery (`io.rs` — a map save to the song's own path writes the sidecar alone and fingerprints `source_bytes`, Save As copies `source_bytes` or an edited score's `write_smf`, both files compared by content before the first write — a changed sidecar `SidecarChanged` unless `SaveIntent` overwrites, a changed score adopted — `rendered_files`; `io/paths.rs` — `saveable_song_path`, the path rule Save and the web import share, `sample_directory`; Save takes any name `external_tools::is_midi_path` accepts, so a `.midi` saves in place beside its `.midi.ron`; `io/commit.rs` — the journal, the finals with an edited score guarded against a `.mid` rewritten under it (kept as `<stem>.recovered-<fingerprint>.mid`), the prune last with every recovery's sidecar a root; `io/open.rs` — every journal file kept as a recovery, never promoted, the finals opened as they are, a journal with no finals made the finals, a `.mid` its sidecar fingerprints differently opened on the disk's bytes with the diff's lines, an unmapped `.mid` opened in place on `scaffold_song_file`; `io/recover.rs` — the recovery's free name, its sidecar the MIDI name plus `.ron`; `io/init.rs` — `init_song`, the scaffold sidecar `song init` writes; `io/samples.rs` — the song's sample folder, its owner-naming `LICENSE`, and the song's own stanza in its home folder's `LICENSE`). `SetProvenance` is the song's own author and license, which Save requires.
- `composer/` — the song's panel, data and drawing only (the host owns the song, the drag and what each action does): `state.rs` (`ComposerState` — `ComposerFocus` and Tab's cycle, the one active track among the tracks with a channel, the four scroll states, the zoom, the keyboard cursors, the control requests a key leaves for the next render, the Songs list — `rescan_songs` reads `external_tools`' `scan_songs` and `scan_sound_fonts`; `songs_scanned` is cleared once per close, on `panel_drawn`'s edge, since the sound emitter's song rule shares the list and a clear on every hidden frame had it scanning each frame, and `drawn()` tells the panel's draw to scan again after a scan the rule made while it was hidden — which `state.rs` and `mod.rs` re-export — `step_sidebar_section` over the section starts the sidebar records each frame, and `follow`, which resets it all when the host's song generation moves), `layout.rs` (`compute` — Full, Compact below 720 px with one sidebar section behind tabs, Tabs below 480 px with one area at a time — and `PianoRollGeometry`: `tick_to_x`/`x_to_tick`/`pitch_to_y`/`y_to_pitch`, `note_rect`, `beat_lines` over the tempo map, thinned at the grid's LOD), `keys.rs` (`COMPOSER_KEYS`, the key table as data, and `resolve`), `piano_roll.rs` (wheel scroll and zoom, the notes drawn from a `MovePreview`, a press that selects and begins a drag, a Ctrl+press that toggles), `note_list.rs` (a row of text per note, units named), `sidebar.rs` with `sidebar/walk.rs` (every control counted so the arrows' cursor and the render agree, every note wrapped to the sidebar's width) and `sidebar/blocks.rs` (parts and the Add-track row — a program field and a name field, Enter adding one `AddTrack` on the next free channel — instruments with provenance, bindings, each with a remove button), the Song section's SoundFont row (cycling `external_tools::scan_sound_fonts`' banks), `transport.rs` (the track selector, the preview's Play and Stop — disabled during a play session — the zoom, and `status_text` — where the preview is, with BPM and meter, in text), the playhead line in `piano_roll.rs` at the tick the host writes into `ComposerState.playhead_tick`, and the song's Author and License fields in the sidebar's Song section; `mod.rs` holds `ComposerAction`, `clamp_move` and `moved_notes_edit` (the one `Batch` a drag or a nudge commits) and `drop_action`.
- `console.rs` — `ConsoleLog`: at most `CONSOLE_CAPACITY` (500) entries, the oldest dropped first, each with an `id` it keeps for the log's life, a `Severity` (`Info`, `Error`), its text, an optional `OpenRequest` (what a click on it opens) and a repeat count; a line collapses into the **last** entry when its severity, location and text match with every run of digits taken as one — keeping the newest text and counting up — so an error every frame is one entry, and a different text at one location, the same text at another line or severity, or a match with an earlier entry but not the last starts a new one. `ConsoleState` (on `EditorContext.console`) adds the shared `ScrollState`, `holds_keyboard`, the `focused` entry the arrows walk (`step_focus`: Up first focuses the newest, Down the oldest; the focus follows its entry past an eviction), `reveal_focused`, `scrolled_up` (the view stands above the newest entry, so new lines leave it where it is), `rows_dropped` (the entries dropped since the panel last drew, which a scrolled-up view moves up by), `focused_request` for Enter and `clear`. The host writes it and the status bar through one function (`editor_integration`'s `editor_game/console.rs`).
- `settings_panel.rs` — the External Tools panel (`SettingsPanelState` on `EditorContext.settings`): `holds_keyboard`, `cursor` and `control_count` (the walk's controls, counted as the composer sidebar counts them, `step_cursor` held inside them and setting `reveal`), the shared `ScrollState`, `request` (`SettingsRequest::Activate` — a button presses, a field takes the keyboard, a cycle steps forward — or `Cycle { forward }` on a cycle row; the next render carries it out, since only the walk knows which control sits at the cursor), the `draft` (`TemplateDraft { slot, text, error }`), `kept_custom` (the custom tool each row cycled away from this session, restored when the row comes back to Custom — stepping through the cycle to look is no edit of the command) and `tool_tests` (the categories whose Test was pressed, drained by the host with the open requests). `render_settings_panel` lays, top to bottom, a heading and a Tool cycle per category (its chosen value applied after the row's fields have drawn, so a press on the cycle commits a focused field first — applied before them, the field the new choice hides kept the keyboard with nothing drawn to let it go, its text unsaved) (System default, the category's presets in table order, Custom command), under a preset its Program field, under Custom its Command field and, for Code, its Project command, and a Test button (disabled on the web over `DESKTOP_ONLY_HINT`); then an override cycle row per `FileType` (Inherit (<the category's tool>), the presets, Custom command, System default) with the same fields; then the DAW project extensions. `settings_panel/walk.rs` is the walk on `composer/sidebar/walk.rs`'s model, laying `field_widgets::edit_cycle`, `text_field::edit_string_validated` and `ui.button_styled` with `theme.editable_field_style()`, the cursor's control ringed in `focus_ring` at 2 px while the panel holds the keyboard; the walk reads the focused widget once at its start (`ui.focused_widget`), since a field drawn earlier in the frame may take the focus from one drawn later, which still has to commit on the press that moved it; a keyboard commit is told from a press away by `ui.commit_key_pressed`; a focused field scrolled out of the panel is drawn off-screen, so its keys and its commit still land (the ui keeps a focused field until it is drawn) and every press is a press away; a failed Enter there re-focuses the field and asks the walk to reveal it with the error row under it (`reveal_control` — applied from the walk's own measure on that frame and again from the drawn control at the next render, since a draft dropped or taken on the same frame moves every row under it), so the keyboard is never held by a field and an error row nobody sees. `settings_panel/rows.rs` is the rows' data, pure over the config: `cycle_values`, `option_name`, `current_option`, `choose` (Custom keeps a chosen custom tool's commands; an override's Inherit removes its entry and every other value writes one, the system default included) and `choose_remembering` (the same with `kept_custom`), `check_template` (a command parses and names `{file}`; a project command parses, blank being none), `commit_template`, `write_program` (blank removes the entry), `parse_extensions` (split on whitespace and commas, kept as typed). The draft rule: a command whose commit fails is never written — the config stays, the text becomes the draft, shown in the field, and an "Error: …" row in `status_error` under it says why in words; a failed Enter re-focuses the field on the draft (the typist's next key is the fix, and unfocused it would reach the editor's shortcuts — Delete the selected entity), while a failed press away lets the keyboard go (re-focused, every press away would commit, fail and take the keyboard back — a trap, and one that held the game's keys when the press was on Play); a click back into the field edits the draft, a passing commit clears it, and Escape in the field drops it and shows the saved value. Every edit writes `EditorContext.external_tools` at once; the host's preferences settle rule persists it, and `render_settings_panel` returns whether the DAW extension list changed, which the host answers by marking the asset browser unscanned.
- `status_bar.rs` — `StatusBar`: `show_message` (timed), `show_error` (persistent, logged, drawn "Error: " in `status_error`), `show_linked_error` (an error with the `OpenRequest` a click on it files), `show_notice` (never displaces an error), `clear_message`. Every message but a linked error drops the link, so a click on "Saved" never opens a stale script. `render` returns the request a click on a linked error filed, through the ui's interaction so a scrim or an open menu blocks it, asks for the pointer while hovered, and tooltips, over the text's own rect, what the click opens — the file and the line — after the whole text when the message is ellipsized.
- `drag_drop.rs` — `DragDropState`/`DragPayload` (`Texture`, `Script`, `Sound`, `Song`, `SoundFont`) cross-panel drag state machine (Idle→Armed→Dragging→Dropped-1-frame).
- `dock/` — multi-panel docking: state, layout, collapse/visibility toggles (`show_panel`: visible, expanded, and a side panel as the narrow overlay while the dock is narrow — a second ask keeps it open), chevrons, and clamped resize grabbers (a hovered or dragged handle draws its grabber line and asks `ui.request_cursor` for `ColResize`/`RowResize`, the dock having no window to ask itself). Below `MIN_CENTER_WIDTH` of centre it enters **narrow mode**: the side panels leave the edge allocation and one at a time shows as an overlay over the viewport on the floating band, opened from its header tab at the edge and closed from its own chevron (`narrow_overlay`, `open_narrow_overlay`, `close_narrow_overlay`); a collapsed panel opens as a full overlay (`expanded_content_bounds`) without touching its persisted collapse flag; the overlay runs to the dock's bottom, over a bottom panel. The bottom edge stacks its panels in the order they were added — Assets, then the Composer, then the Console, each hidden until asked for — never side by side or as tabs. The seventh panel, External Tools (`PanelId::SETTINGS`), is added last on the right edge, hidden, and no View item toggles it; the first layout pass gives each visible right panel the full remaining height, so it sits beside the Inspector, not under it. Narrow-mode tabs sharing an edge stack downward in the panels' order, one tab length and a padding apart, every side panel on the edge holding its slot — the overlay's left empty — so no tab moves when a neighbour opens or closes.
- `toolbar_strip.rs` — the scene view's toolbar strip: `split` (panel content → strip + viewport), the `begin`/`end` chrome scope on `UiLayer::PanelChrome`, and `layout` placing the tools left, the play controls at the centre where it leaves them whole, and the view group (`VIEW_GROUP_WIDTH`, 140 px) at the right edge; below `TOOLBAR_STRIP_MIN_WIDTH` (391 px) the view group sheds whole and the tools shed one by one into the overflow menu (`overflow_menu.rs`).
- `menu/` — top menu bar; action items carry checked flag and map labels to `EditorAction`. View → Inspector, Hierarchy, Asset Browser, Composer and Console toggle their panels (`panel_id_for_menu_label`); only Scene View draws disabled. Edit ends with "Open Project in <tool>" — named each frame by `open_project_item` from the code tool's `ToolName` ("Open Project with the custom command", "Open Project with the system default", the last disabled, as is the item on the web) and found again by `MenuBar::set_action_by_prefix`, since `action_for_menu_label` maps any label starting with `OPEN_PROJECT_PREFIX` to `EditorAction::OpenProject` — and "External Tools…" (`EditorAction::ShowExternalTools`); both are allowed while playing. The dropdown's geometry and drawing (`dropdown_bounds`, `measured_width`, `dropdown_item_bounds`, `render_dropdown_static`) are `pub(crate)`, shared with the context menu rather than copied. A press of either button outside the open dropdown closes it, so a right press beside it never leaves it open under a context menu.
- `context_menu.rs` — `ContextMenu` (on `EditorContext.context_menu`): a few `ContextMenuItem`s over one thing, opened at a point by a right press on an asset tile or a `Scripts` pseudo-row, or from the keyboard, and drawn with the menu bar's dropdown, a little wider for the keyboard's ring, on `UiLayer::Modal` — the colour editor's band, above a narrow-mode panel overlay on `Floating` — by a pass that runs before the menu bar and every panel, so its blocking rect reaches what it covers; a confirm dialog coming up closes it. Up and Down walk the enabled items (`ContextMenuKey`, through the host's key route), Enter chooses, every other key is swallowed while it is open, and Escape or a press outside closes it — the outside press swallowed whole, behind a window-wide blocking rect for that frame. The dropdown, the colour editor and a focused edit field all yield to a right press outside them, so the menu never opens beside another popup or under a field that keeps its keys. `open_for_file` builds a file's two items: Open in the tool it resolves to (`ExternalToolsConfig::tool_name`) and Open containing folder; on the web both draw disabled over `DESKTOP_ONLY_HINT`.
- `double_click.rs` — `DoubleClick<Target>`, the one double-click rule: a second left press on the same target within 400 ms and 4 px of the first, no drag started between them (the surface calls `forget`); a completed double-click is forgotten, so a triple press is one. The `ui` crate knows nothing of it.
- `editor_input.rs` — shortcut chord model (exact chord beats any-mods) and `allowed_while_playing()` action deny list.
- `archetype.rs` — `Archetype`: the nine entity factories shared by the Entity menu and command API `create`.

- `external_tools/` — which program opens which project file, pure and tested; `editor_integration`'s launcher spawns. `file_type.rs` is the one table: `FileType` → `ToolCategory` (Code, Music, Sample, Art; `ALL` and `name` for each, in the order the settings panel lists them), the `{project}` base and the `ReloadPolicy` (a `.ron` by its sidecar suffix), plus `is_midi_path`, `midi_sidecar_path` and its inverse `sidecar_midi_path` — the only place the MIDI extension rule (`mid`/`midi`, any case) and the `<name>.<ext>.ron` sidecar rule live. `template.rs` is the group-first `CommandTemplate` grammar (`[ … ]` groups drop when a placeholder of their own is missing, a group against a word joins it, quoted spans, values never re-split; `{file}`, `{project}`, `{line}`, `{column}`, `{track}`, `{track_index}`, any other an error). `config.rs` holds `ToolChoice` (`Preset`, `Custom(CustomTool)`, `OsDefault`), `ExternalToolsConfig` (on `EditorContext.external_tools` and the prefs; the preset's own bare name typed there, with or without Windows' executable extension (`exe`, `com`, `bat`, `cmd`) and in any case, is its own program, fallbacks and all, while any other suffix is another name and a path is the person's file whatever it is called — a blank or absent entry keeping the preset's own), `OpenRequest` and `Location`, `ToolName` — what a choice is called, `tool_name(file_type)` naming the context menu's "Open in RustRover" / "Open with the system default" from the same `subject` `resolve`'s errors begin with, so the two never disagree — `os_default` (the platform's opener, a folder included), `DESKTOP_ONLY_HINT`, and `resolve`: a present override whatever it says, else the category's choice, `OsDefault` being the platform's opener — `$VISUAL` and `$EDITOR` are never read, since they almost always name a terminal editor; a project request goes through the category's choice alone (a project is no file, and an override says how a file opens) — a preset's project template, or a custom tool's project command — and is refused with `NoProjectCommand` — naming Edit → External Tools… — for one without and for the system default. `resolve_with` resolves through a choice given, whatever the config would pick for the file: a category's Test. `custom_tool.rs` is `CustomTool { file, project: Option }` (`file_only` for the one-command tool): serialized as the struct, deserialized through an untagged shape that reads a bare string as `file_only`. `presets.rs` is the preset table as data, each row's source page in its doc comment. `songs.rs` holds the project's songs as the tools see them: `scan_songs` (every `is_midi_path` file under `music/` and `ai/music/`, the composer's Songs list), `read_song_pair` (a song's `.mid` and sidecar read through `common::vfs`, never through the document's open, which may write), and the pure track resolution — `part_location` (`Part::resolve_track` and the track's name, a nameless track `name: None`), `binding_location` (action → binding → part, an unknown action a `BindingLookupError` listing the sidecar's actions) and `first_part_location`. `track_diff.rs` is the pure track diff over two `TrackListing`s (each part as `part_location` resolves it, and the track names by `SongData` index): a `Name` part unchanged wherever its track moved, an `Index` whose name changed refused naming both, a track gone refused with the rename hint when a new name sits at its index, an ambiguous name refused with the `Index` hint, a changed selector accepted and reported, a new unselected track background; `DiffLine { text, severity }` with refusals first, and `TrackDiff::refuses`. `sound_fonts.rs` is `scan_sound_fonts` over `soundfonts/` and `sound_font_exists`. `watch.rs` is `FileWatch`, pure over `common::vfs::change_stamp` (or the readings `poll_with` is handed): the registered set kept apart from what each poll observed; `poll()` reports a path's `FileChange` once its new reading has held for one further poll; a missing path stays registered as a tombstone, reported `Deleted` after two polls and `Changed` whenever it returns, so an unlink-then-create save inside the window is one change; a `.mid` and its `.mid.ron` (by `is_midi_path` and `midi_sidecar_path`) settle together; `set_registered(paths, expected_absent)` takes, beside the set, the paths the host believes missing, and a path newly marked — not marked at the last registration — is taken as absent whatever was observed of it, so a file found there, at its first poll or already read as present before the host's own read failed, is a change, not a silent baseline (a mark repeated is no news); `note_written(path, stamp)` takes the stamp the editor read after its own write as the path's state and drops a change pending its debounce; `WatchEvent` is what the thread polling it sends its host, a change or that it took a note, in order. The thread that polls it is `editor_integration`'s.

## Key Patterns
- Inspector uses `serde_json::to_value()` to extract component fields generically
- Component editors return `Option<ComponentEdit<T>>` (full new value + `field_hint` for undo merging) that the integration crate applies via `apply_component_edit()`
- `EditorPlayState::Editing` → editable, `Playing` → the same rows drawn read-only, `Paused` → editable; `CommandHistory::begin_session` marks the Play boundary the editor's Stop dialog acts on
- The inspector heading is two lines: `entity_display_name` on top, then `Selection::inspector_heading`'s detail line ("Entity 17", or "3 selected · Entity 17 primary")
- Selection: `editor.selection.primary()` returns the main selected EntityId
- Gizmo drag tracking: editor_integration's `GizmoDragState` captures start transform+collider for every selection root; frames apply `start + cumulative delta` (idempotent — what makes snapping residual-proof), ONE Macro/TransformGizmo command on release, Escape restores starts and pushes nothing
- The toolbar and the play controls are NOT floating chrome: they render inside the strip's scope, positioned by `toolbar_strip::layout`. `scene_view_bounds()` is the viewport BELOW the strip — every overlay, the GPU scissor and every pick map through it, so none of them reach into the band; `toolbar_strip_bounds()` is the band itself.
- Theme is on `EditorContext.theme` (public field); call `theme.gizmo_palette()`, `inspector_style()`, `editable_field_style()`, `grid_colors()`, `collider_overlay_colors()`, `game_frame` instead of hardcoding colors. Menu/Toolbar/Hierarchy `render()` take `&EditorTheme`
