# Editor Crate — Agent Context

You are working in the editor crate. UI panels, tools, inspector, hierarchy — the editor's data and widgets.
This crate has NO dependency on engine_core. It depends on: ecs, ui, input, renderer, physics, common, and music_midi without its `synth` feature (the Conductor panel edits and saves songs, never renders them — `cargo test -p editor` alone is what proves that build).

## UI scale

`EditorPreferences.ui_scale` is `UiScale::FollowDisplay` (JSON `"follow"`, also the default
when absent) or `Percent(u16)` (JSON number). `resolve_ui_scale` is the single finite
0.5–4.0 pixels-per-point resolver, with zero and non-finite values falling back to 1.0.
View → UI Scale offers Follow the display with its live percentage and 100–200 % in 25 %
steps; Ctrl++ (or Ctrl+=) / Ctrl+- step and Ctrl+0 returns to Follow. All layout tokens, icon weights,
fonts and overflow clamps are points. The physical minimum remains 1024×720, so at 200 %
a 1024 px window is 512 pt and the dock deliberately goes narrow.

The three physical seams are `EditorInputMapping::update_state(input, scale)` (pointer
position and motion to points, not wheel notches), `SceneViewport::to_window_render_camera`
(window in physical pixels plus scale), and `physical_viewport_bounds` (near edges floored,
far edges ceiled, shared by the GPU camera and scissor). The editor camera, picking, pan,
marquee and gizmos stay in points. `ViewportInputHandler::handle_input_simple` forwards
the resolved scale to the input boundary.

`menu/dropdown.rs` lays child dropdowns to the right, else left, else clamped over their
parent. The topmost region owns pointer input when they overlap. `menu/keyboard.rs`
walks the open path with Up/Down, Right/Enter and Left; Escape closes the whole path.
The host routes every key to the open menu before panel or game shortcuts.

## Architecture
```
EditorContext (selection, tool state, play state, camera, theme, status_bar, fonts, inspector_scroll)
│   (CommandHistory itself lives on editor_integration's EditorGame and is threaded into panel renderers)
├── Panels: SceneView, Hierarchy, Inspector, AssetBrowser, Conductor (hidden until a song asks for it), Console (hidden until View → Console asks for it), External Tools (hidden until Edit → External Tools… asks for it)
├── Dock layout: dock/ (edge tab groups, narrow overlays and an effective vertical budget)
├── Menu / StatusBar (top + bottom chrome; an error naming a file carries its request, and a click on it opens the file); Toolbar + PlayControls in the scene view's toolbar strip
├── Tools: Select, Move, Rotate, Scale (Q/W/E/R shortcuts)
├── Gizmos: Translate, Rotate, Scale handles
├── Picking: EntityPicker, SelectionRect, screen_to_world()
├── Inspector: Generic serde-based + per-component editors with writeback
│   (one renderer: `InspectorFrame.read_only` draws every row's value in
│   place of its control while a play session runs; sections collapse and
│   an Advanced disclosure hides the rarely-touched fields)
├── Undo/Redo: CommandHistory + EditorCommand trait, StoredComponent for restore
├── Theme: EditorTheme with 30+ color tokens (mockup-derived)
└── Play state: EditorPlayState (Editing/Playing/Paused), WorldSnapshot
```

`rendered_files`; `io/paths.rs` — `saveable_song_path`, the path rule Save and the web import share, `sample_directory`; Save takes any name `external_tools::is_midi_path` accepts, so a `.midi` saves in place beside its `.midi.ron`; `io/commit.rs` — each final written to `.<name>.saving` beside it and renamed over it through `SongStore::rename`, so a save stopped at any write leaves the old finals whole, then the prune; `io/open.rs` — the finals opened as they are, a `.mid` its sidecar fingerprints differently opened on the disk's bytes with the diff's lines, an unmapped `.mid` opened in place on `scaffold_song_file`, nothing written; The host writes it and the status bar through one function (`editor_integration`'s `editor_game/console.rs`).
- `settings_panel.rs` — the External Tools panel (`SettingsPanelState` on `EditorContext.settings`): `holds_keyboard`, `cursor` and `control_count` (the walk's controls, counted as the Conductor panel's sidebar counts them, `step_cursor` held inside them and setting `reveal`), the shared `ScrollState`, `request` (`SettingsRequest::Activate` — a button presses, a field takes the keyboard, a cycle steps forward — or `Cycle { forward }` on a cycle row; the next render carries it out, since only the walk knows which control sits at the cursor), the `draft` (`TemplateDraft { slot, text, error }`), `kept_custom` (the custom tool each row cycled away from this session, restored when the row comes back to Custom — stepping through the cycle to look is no edit of the command) and `tool_tests` (the categories whose Test was pressed, drained by the host with the open requests). `render_settings_panel` lays, top to bottom, a heading and a Tool cycle per category (its chosen value applied after the row's fields have drawn, so a press on the cycle commits a focused field first — applied before them, the field the new choice hides kept the keyboard with nothing drawn to let it go, its text unsaved) (System default, the category's presets in table order, Custom command), under a preset its Program field, under Custom its Command field and, for Code, its Project command, and a Test button (disabled on the web over `DESKTOP_ONLY_HINT`); then an override cycle row per `FileType` (Inherit (<the category's tool>), the presets, Custom command, System default) with the same fields; then the DAW project extensions. `settings_panel/walk.rs` is the walk on `conductor/sidebar/walk.rs`'s model, laying `field_widgets::edit_cycle`, `text_field::edit_string_validated` and `ui.button_styled` with `theme.editable_field_style()`, the cursor's control ringed in `focus_ring` at 2 px while the panel holds the keyboard; the walk reads the focused widget once at its start (`ui.focused_widget`), since a field drawn earlier in the frame may take the focus from one drawn later, which still has to commit on the press that moved it; a keyboard commit is told from a press away by `ui.commit_key_pressed`; a focused field scrolled out of the panel is drawn off-screen, so its keys and its commit still land (the ui keeps a focused field until it is drawn) and every press is a press away; a failed Enter there re-focuses the field and asks the walk to reveal it with the error row under it (`reveal_control` — applied from the walk's own measure on that frame and again from the drawn control at the next render, since a draft dropped or taken on the same frame moves every row under it), so the keyboard is never held by a field and an error row nobody sees. `settings_panel/rows.rs` is the rows' data, pure over the config: `cycle_values`, `option_name`, `current_option`, `choose` (Custom keeps a chosen custom tool's commands; an override's Inherit removes its entry and every other value writes one, the system default included) and `choose_remembering` (the same with `kept_custom`), `check_template` (a command parses and names `{file}`; a project command parses, blank being none), `commit_template`, `write_program` (blank removes the entry), `parse_extensions` (split on whitespace and commas, kept as typed). The draft rule: a command whose commit fails is never written — the config stays, the text becomes the draft, shown in the field, and an "Error: …" row in `status_error` under it says why in words; a failed Enter re-focuses the field on the draft (the typist's next key is the fix, and unfocused it would reach the editor's shortcuts — Delete the selected entity), while a failed press away lets the keyboard go (re-focused, every press away would commit, fail and take the keyboard back — a trap, and one that held the game's keys when the press was on Play); a click back into the field edits the draft, a passing commit clears it, and Escape in the field drops it and shows the saved value. Every edit writes `EditorContext.external_tools` at once; the host's preferences settle rule persists it, and `render_settings_panel` returns whether the DAW extension list changed, which the host answers by marking the asset browser unscanned.

Every message but a linked error drops the link, so a click on "Saved" never opens a stale script. `render` returns the request a click on a linked error filed, through the ui's interaction so a scrim or an open menu blocks it, asks for the pointer while hovered, and tooltips, over the text's own rect, what the click opens — the file and the line — after the whole text when the message is ellipsized.
- `drag_drop.rs` — `DragDropState`/`DragPayload` (`Texture`, `Script`, `Sound`, `Song`, `SoundFont`) cross-panel drag state machine (Idle→Armed→Dragging→Dropped-1-frame).
- `dock/` — `mod.rs` holds panel identities and registration defaults; `groups.rs` owns `TabGroup` membership, visibility, activation and moves; `layout.rs` computes allocations; `render.rs` draws the tab strips, overflow, chevrons and resize handles; `focus.rs` walks the group strips. Tabs take their title's width (48 to 192 points, measured as the strips draw), shrink in proportion under pressure to the 48-point minimum, and excess tabs live behind `»`; the focused or active tab remains visible. ### Persistence + commands
- `confirm_dialog.rs` — the Modal-band `ConfirmDialog`: the scene's unsaved-changes prompt, the Stop prompt, the song's (`unsaved_song`), Play's over a dirty song (`play_with_unsaved_song`: Save / Play saved / Cancel, or Save / Cancel for a song never saved — the alternative button is `alt_label: Option`), Save As's onto another song (`overwrite_song`: Overwrite / Cancel) and the open scene's when another program rewrote it under unsaved edits (`scene_changed_on_disk`: Reload / Keep mine, the message saying Reload discards the edits). ## Key Patterns
- Inspector uses `serde_json::to_value()` to extract component fields generically
- Component editors return `Option<ComponentEdit<T>>` (full new value + `field_hint` for undo merging) that the integration crate applies via `apply_component_edit()`
- `EditorPlayState::Editing` → editable, `Playing` → the same rows drawn read-only, `Paused` → editable; `CommandHistory::begin_session` marks the Play boundary the editor's Stop dialog acts on
- The inspector heading is two lines: `entity_display_name` on top, then `Selection::inspector_heading`'s detail line ("Entity 17", or "3 selected · Entity 17 primary")
- Selection: `editor.selection.primary()` returns the main selected EntityId
- Gizmo drag tracking: editor_integration's `GizmoDragState` captures start transform+collider for every selection root; frames apply `start + cumulative delta` (idempotent — what makes snapping residual-proof), ONE Macro/TransformGizmo command on release, Escape restores starts and pushes nothing
- The toolbar and the play controls are NOT floating chrome: they render inside the strip's scope, positioned by `toolbar_strip::layout`. `scene_view_bounds()` is the viewport BELOW the strip — every overlay, the GPU scissor and every pick map through it, so none of them reach into the band; `toolbar_strip_bounds()` is the band itself.
- Theme is on `EditorContext.theme` (public field); call `theme.gizmo_palette()`, `inspector_style()`, `editable_field_style()`, `grid_colors()`, `collider_overlay_colors()`, `game_frame` instead of hardcoding colors. Menu/Toolbar/Hierarchy `render()` take `&EditorTheme`
